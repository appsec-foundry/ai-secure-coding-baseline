# Requirements

## NOTE-NAME-001 Use a neutral attributed heading

Source: the user's request and explicit approval in this session to use a more
neutral security-note label while retaining its baseline attribution.

When the baseline requires its closing security note, its heading describes it
neutrally and identifies the baseline as its source.

Acceptance: a qualifying completion uses a neutral, baseline-attributed heading
without presenting the note as a general review or assurance report.

## NOTE-NAME-002 Preserve risk-only reporting

Source: `secure-coding-baseline.md` rule group `AISEC-REPORT-001` and archived
requirements `SCOPE-004` and `SCOPE-006`, whose reporting logic the user asked
to keep unchanged.

Renaming the note does not change its trigger or contents: it appears only when
the delivered state creates or materially worsens a qualifying security risk,
and it contains only those risks.

Acceptance: accepted trade-offs still produce one attributed note, while a
change with no qualifying adverse security change produces none.
