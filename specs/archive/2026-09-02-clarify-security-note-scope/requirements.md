# Requirements

## NOTE-SCOPE-001 A refusal exempts only itself

Source: the user's request and approval in this session after a content
review of the security-note rules.

A refusal or an expressly requested risk review needs no security note of its
own. A qualifying risk that the delivered part of the same response creates or
materially worsens still gets one.

Acceptance: a mixed request whose delivered part carries an accepted security
trade-off produces the attributed note; a response that only refuses produces
none.

## NOTE-SCOPE-002 Other qualifying issues go in the main answer

Source: the user's request in this session, `aiscb-OM-001` ("Report concrete
pre-existing security issues encountered in scope"), and the existing
`aiscb-REPORT-001` sentence that forbids repeating a risk between the main
answer and the note.

A qualifying issue that the change touched but did not create or materially
worsen is reported once in the main answer and never in the note.

Acceptance: a touched pre-existing weakness that meets the reporting threshold
appears in the main answer, and no note is produced for it.
