# Clarify the scope of the security note

## Problem

`aiscb-REPORT-001` leaves two questions open. "An expressly requested risk
review or refusal needs no additional note" can be read as exempting a whole
response that contains a refusal, even when the delivered part creates a
qualifying risk. And the rule never says where a qualifying issue goes when it
does not meet the note trigger; the main answer is implied only by the
sentence that forbids repeating a risk between the main answer and the note.

## Goal

State in the same rule group that a refusal or requested review exempts only
itself, and that every other qualifying issue is reported once in the main
answer. The note's trigger, contents, and ordering stay as they are.

## Non-goals

No version change. No position for the note within a response. No change to
`aiscb-OM-002` or to which risks qualify.

## Compatibility

The heading is unchanged and existing model checks keep matching. The change
only removes two readings the baseline never intended.
